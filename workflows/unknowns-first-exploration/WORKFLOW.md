# Unknowns-First Exploration

Use this workflow when the right implementation cannot be chosen safely from
the initial request alone.

## 1. Scan and open on settled ground

Inspect the relevant repository, references, half-built attempts, and
conventions. Open with what is settled, what is assumed, file citations, a
load-bearing finding if present, and the next three stages.

## 2. Name and close the questions

List the questions that can block progress. Ask one at a time in blast-radius
order and give a recommended answer with short options. Read the territory for
questions it can answer. Record every result as user-answered,
territory-answered, or `OPEN` with an unblocker.

## 3. Make tacit preferences reactable

Show a concrete artifact grounded in real data. Ask who consumes it, where it
runs, and what done means to the inheritor. Record the user's reaction and
the vocabulary or convention it reveals.

## 4. Sweep for landmines

Cover every file or surface the task will touch. Report silent traps,
unwritten conventions, prior attempts, and inherited findings as evidence
cards. Escalate findings that change a decision; mark awareness-only findings
as sharp edges.

## 5. Hand over a living map

Assemble the four quadrants, decisions, extracted context, landmines, open
items, and small pre-build confirmations. Add a tweakable plan ordered by
judgment calls and a copyable implementation prompt. Keep implementation
separate until the user accepts the map.

## 6. Carry the map forward

Log deviations during implementation and fold new surprises into the map.
Package the map with the review pitch before shipping, and use a quiz before
merging an inherited or long change. See the [skill contract](../../skills/unknowns-first-exploration/SKILL.md).
