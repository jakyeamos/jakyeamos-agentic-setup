# Recurring-loop authorship

## Why this was promoted

The source practice turns a repeated personal loop into a workflow specification
that another person or agent can customize. Its advantage is capturing the
trigger, output, state, checkpoints, retries, and stopping condition without
requiring the adopter to copy the author's complete setup.

## Public reduction

The public skill interviews one decision at a time, recommends a safe default,
and keeps unresolved fields visibly `OPEN`. It separates portable behavior from
local adapters, preserves human approval boundaries, and requires persistence,
duplicate handling, escalation, verification, and readiness before an
implementer is expected to build. One question means one spec dimension, not a
questionnaire disguised as a sentence.

## Blind evaluation

The first judge found one bundled question covering retries, persistence,
resume, and blocking. The contract was tightened so each turn closes only one
spec dimension. The final separate judge evaluated three trigger cases and one
non-trigger case:

- Trigger cases: 3/3 passed.
- Non-trigger cases: 1/1 passed.
- Decision: **Promote** as an experimental public skill.

## Evidence boundary

This proves the interview and safety contract for the sanitized skill. It does
not create a schedule, authorize an account, choose a destination, send an
outbound message, or claim that an authored workflow is ready without the
remaining user decisions.
