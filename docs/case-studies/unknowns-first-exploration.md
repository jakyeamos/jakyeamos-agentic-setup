# Unknowns-first exploration

## Why this was promoted

The source practice makes exploration a visible deliverable: settled ground,
named decisions, tacit preferences extracted through concrete artifacts, and
landmines discovered by a bounded sweep. The multiplier is handing someone a
map and a customizable prompt before handing them a hardened implementation.

## Public reduction

The public skill preserves the four stages—known knowns, known unknowns,
unknown knowns, and unknown unknowns—plus the living map, tweakable plan, and
copyable implementation prompt. It makes the stage order fail-closed, keeps
implementation separate, requires evidence provenance, and requires a real
question or artifact for the user's reaction. When the territory is
unavailable, it asks for exact scope/access or shows a labeled scan manifest;
it does not pretend to have inspected files.

## Blind evaluation

The first judge found a premature handoff and a future inspection instruction
standing in for a reaction. The contract was tightened so stages 1–4 must be
completed in order, unscanned facts stay labeled, and the clean-room stage-1
fallback is explicit. The final separate judge evaluated three trigger cases and
one non-trigger case:

- Trigger cases: 3/3 passed.
- Non-trigger cases: 1/1 passed.
- Decision: **Promote** as an experimental public skill.

## Evidence boundary

This proves routing and stopping behavior for the public exploration contract.
It does not claim that every task needs a map, that a user must accept a single
design process, or that the map itself resolves decisions without user
reaction.
